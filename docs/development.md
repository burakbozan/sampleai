# Development Guide

Principles:
- Domain-Driven Design (DDD): separate bounded contexts as services.
- Behavior-Driven Development (BDD): write Gherkin scenarios for business behavior.
- Test-Driven Development (TDD): unit + integration tests before implementation.
- Use Gang of Four patterns where appropriate (Factory, Repository, Adapter, Strategy).
- Follow 12-factor app principles for config, backing services, logs, processes.

Folder layout, CI, and commit rules are under CODE_REVIEW_RULES.md and docs/.
